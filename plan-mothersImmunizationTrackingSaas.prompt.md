# Plan: Mothers' Immunization Tracking SaaS (Multi-Tenant with Subdomains)

Building a multi-tenant health SaaS with hospital-managed vaccine catalogs (versioned), comprehensive notifications, per-channel opt-out with audit, Super Admin visibility into all data, full export with audit logging, automated hospital performance alerts with escalation, and dual-notification to both Hospital Admin and Super Admin.

## Steps

### 1. Update Prisma Schema

Update `prisma/schema.prisma` with the following models:

- **Hospital**: `slug`, `status`, `notificationSettings` JSON, `overdueThreshold`, `alertsEnabled`
- **User roles**: `SUPER_ADMIN`, `HOSPITAL_ADMIN`, `HEALTH_WORKER`, `PARENT`
- **HealthWorker permissions**: `canRegisterMothers`, `canRegisterChildren`, `canRecordImmunizations`, `canViewAllPatients`
- **HospitalVaccine**: `hospitalId`, `name`, `shortName`, `description`, `manufacturer`, `dosesRequired`, `minAgeWeeks`, `maxAgeWeeks`, `intervalWeeks`, `reminderDaysBefore`, `isActive`, `currentVersionId`, `createdById`
- **HospitalVaccineVersion**: `vaccineId`, `versionNumber`, `name`, `minAgeWeeks`, `maxAgeWeeks`, `intervalWeeks`, `dosesRequired`, `changedById`, `changedAt`, `changeReason`
- **Mother/Child**: `registeredById`, `registrationType`, `currentHospitalId`
- **MotherNotificationPreference**: `motherId`, `emailEnabled`, `smsEnabled`, `pushEnabled`, `optOutAt`, `optOutReason`, `updatedById`
- **NotificationOptOutLog**: `motherId`, `channel`, `action`, `reason`, `performedById`, `performedAt`
- **ImmunizationSchedule**: `autoGenerated`, `isLocked`, `lockedAt`, `lockedById`, `vaccineVersionId`, `reminderSentAt`, `overdueNotificationCount`, `lastNotifiedAt`, `nextNotificationAt`
- **ImmunizationRecord**: Links to schedule, triggers lock
- **Notification**: `type` (UPCOMING/OVERDUE/TRANSFER/SYSTEM_ALERT/PERFORMANCE_ALERT), `channel`, `status`, `scheduledFor`, `sentAt`, `scheduleId`, `recipientId`
- **HospitalNotificationSettings**: `frequency`, `escalationDays`, `enabledChannels`, `reminderDaysBefore`, `quietHoursStart`, `quietHoursEnd`
- **TransferRequest/TransferHistory**: Hospital transfer with audit
- **DataExport**: `id`, `userId`, `exportType`, `scope`, `hospitalId`, `filters` JSON, `format`, `recordCount`, `fileUrl`, `status`, `requestedAt`, `completedAt`, `expiresAt`
- **DataExportAuditLog**: `exportId`, `userId`, `action`, `ipAddress`, `userAgent`, `performedAt`
- **HospitalPerformanceSnapshot**: `hospitalId`, `date`, `totalScheduled`, `totalCompleted`, `totalOverdue`, `overdueRate`, `completionRate`, `createdAt`
- **PerformanceAlert**: `hospitalId`, `type` (OVERDUE_THRESHOLD/COMPLETION_DROP/INACTIVE), `threshold`, `actualValue`, `message`, `severity` (WARNING/CRITICAL), `status` (PENDING/ACKNOWLEDGED/ESCALATED/RESOLVED), `escalationLevel` (1, 2, 3...), `lastEscalatedAt`, `nextEscalationAt`, `triggeredAt`, `acknowledgedById`, `acknowledgedAt`, `resolvedAt`, `resolvedNote`
- **PerformanceAlertRecipient**: `alertId`, `userId`, `role` (HOSPITAL_ADMIN/SUPER_ADMIN), `notifiedAt`, `channel`, `status` (SENT/FAILED)
- **PerformanceAlertEscalationLog**: `alertId`, `escalationLevel`, `escalatedAt`, `recipientCount`, `note`
- **SystemAlertSettings**: `overdueThresholdDefault`, `completionDropThreshold`, `inactivityDays`, `escalationDelayDays` (e.g., 3), `maxEscalationLevel` (e.g., 3), `alertChannels`, `escalationChannels`, `criticalThreshold` (e.g., 40% overdue = critical)

### 16. Create Hospital Performance Service

Create `lib/services/hospital-performance-service.ts`:

- **Daily snapshot job**: Calculate metrics per hospital
- **Alert evaluation**: Compare against thresholds
- **Severity assignment**:
  - WARNING: Exceeds threshold (e.g., 20-39% overdue)
  - CRITICAL: Exceeds critical threshold (e.g., 40%+ overdue)
- **Create alert**: Store with `escalationLevel: 1`, `nextEscalationAt: now + escalationDelayDays`

### 17. Create Performance Alert Service

Create `lib/services/performance-alert-service.ts`:

- **Initial notification** (on alert creation):
  - Notify Hospital Admin(s) of the affected hospital (email + in-app)
  - Notify all Super Admins (email + in-app)
  - Create `PerformanceAlertRecipient` records for tracking
- **Escalation job** (daily cron):
  - Find alerts where `status = PENDING OR ESCALATED` AND `nextEscalationAt <= now`
  - Increment `escalationLevel`, update `lastEscalatedAt`
  - Calculate `nextEscalationAt` (or null if max level reached)
  - Create `PerformanceAlertEscalationLog` entry
  - Re-notify all recipients with escalation message
- **Escalation message templates**:
  - Level 1: "Alert: Hospital X has 25% overdue rate"
  - Level 2: "Reminder: Hospital X alert unacknowledged for 3 days"
  - Level 3: "Urgent: Hospital X alert requires immediate attention"
- **Stop escalation**: When acknowledged or resolved
- **Critical auto-escalate**: If severity = CRITICAL, start at higher escalation level

### 18. Create Alert Notification Templates

Create templates in `lib/email-templates/`:
- `performance-alert-initial.tsx`: First notification with metrics, link to dashboard
- `performance-alert-escalation.tsx`: Escalation notice with level, days unacknowledged
- `performance-alert-resolved.tsx`: Resolution confirmation with notes

## Key Design Decisions

### User Roles & Permissions

| Role | Access | Capabilities |
|------|--------|--------------|
| Super Admin | `admin.marv.com` | View all hospitals, vaccines, mothers; manage system settings; view all alerts |
| Hospital Admin | `{slug}.marv.com` | Manage own hospital's vaccines, workers, patients; view own alerts |
| Health Worker | `{slug}.marv.com` | Register mothers/children (if permitted), record immunizations |
| Parent | Mobile app (Flutter) | View own children's schedules, receive notifications |

### Health Worker Permissions (Configurable per worker by Hospital Admin)

- `canRegisterMothers`: Can register new mothers
- `canRegisterChildren`: Can register children
- `canRecordImmunizations`: Can mark vaccines as given
- `canViewAllPatients`: View all patients vs only own registrations

### Notification Frequency Options (Per Hospital)

- **SINGLE**: One alert when overdue
- **DAILY**: Daily reminders until completed
- **ESCALATING**: Configurable days (e.g., day 1, 3, 7, 14)

### Mother Notification Preferences

- Per-channel opt-out: Email, SMS, Push (future)
- Audit log for all preference changes
- Reason required for opt-out

### Vaccine Versioning

- Edits create new version, existing schedules keep old version
- Full audit trail of changes with reasons
- Schedules immutably linked to version at creation

### Transfer Workflow

- Hospital Admin initiates transfer request
- Target hospital approves/rejects
- On approval: Update `currentHospitalId`, preserve all history
- Existing schedules preserved with original vaccine versions

### Performance Alerts

- **Thresholds**: Overdue rate, completion rate drop, inactivity
- **Severity**: WARNING vs CRITICAL
- **Dual notification**: Hospital Admin + Super Admin
- **Escalation**: Re-notify every X days if unacknowledged
- **Auto-resolve**: When metrics return to acceptable levels

### Data Export

- **Types**: Mothers, Children, Immunizations, Full
- **Formats**: CSV, Excel, JSON
- **Scope**: Hospital-only (Hospital Admin) or System-wide (Super Admin)
- **Audit**: All exports logged with IP, user agent, download tracking
- **Expiry**: Files expire after X days
